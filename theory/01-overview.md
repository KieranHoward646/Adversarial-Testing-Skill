# 01 — 什么是对抗测试？

## 定义

对抗测试（Adversarial Testing）是一种结构化的主动安全实践——由专家或 AI 代理模拟攻击者行为，系统地探测目标系统的漏洞、边界和异常行为，在真实攻击者利用之前发现并修复问题。

## 与普通测试的区别

| | 普通测试 | 对抗测试 |
|---|---|---|
| **目标** | 验证功能按预期工作 | 发现功能在压力/恶意输入下的崩溃 |
| **思维** | "用户会怎么用？" | "攻击者会怎么破坏？" |
| **输入** | 合法范围的正常值 | 恶意构造的极端值、注入载荷 |
| **判定** | PASS/FAIL 二元 | 概率性行为、边缘案例 |
| **测试者** | 开发者自己 | 独立于开发的对抗者（或 AI） |

## 为什么对抗测试在 AI 时代更重要？

1. **非确定性系统**：LLM 的输出不可预测，传统测试无效
2. **自然语言攻击面**：攻击者不需要懂代码，Prompt Injection 用自然语言即可
3. **Agent 自主性**：AI Agent 可以自主执行多步攻击（2025 Anthropic 事件：Claude Code 自主执行了 80-90% 的攻击战术动作）
4. **供应链风险**：恶意 LoRA、投毒数据集、被篡改的模型权重

## 核心概念

| 术语 | 含义 |
|------|------|
| **Red Team** | 模拟攻击的对抗方 |
| **Blue Team** | 防御方，保护系统安全 |
| **Purple Team** | 红蓝协作模式 |
| **Attack Surface** | 系统所有可被攻击的入口 |
| **Jailbreak** | 绕过 AI 安全护栏 |
| **Prompt Injection** | 通过输入文本操控 AI 行为 |
| **Model Extraction** | 通过 API 窃取模型 |
| **Data Poisoning** | 污染训练数据 |
